## 3. Chi tiết từng Model

### 3.1 Enums.cs - Các kiểu liệt kê

**CourseStatus** - Trạng thái khóa học:
- `Draft = 0`: Bản nháp, học sinh không thấy
- `Published = 1`: Đã công khai, cho phép đăng ký
- `Closed = 2`: Đã kết thúc, khóa đăng ký

**FileType** - Loại tài liệu:
- `Pdf = 0`, `Docx = 1`, `Video = 2`, `Link = 3`

**Cách hoạt động**: EF Core chuyển enum thành `int` trong PostgreSQL (cấu hình qua `HasConversion<int>()` trong DbContext). Ví dụ `CourseStatus.Published` sẽ lưu thành `1`.

### 3.2 AppUser.cs - Người dùng

**Kế thừa IdentityUser**, nghĩa là đã có sẵn: `Id` (string/GUID), `UserName`, `Email`, `PasswordHash`, `PhoneNumber`...

**Thuộc tính mở rộng**:
| Thuộc tính | Kiểu | Ràng buộc | Mô tả |
|------------|------|-----------|-------|
| `FullName` | string | `[Required]`, `[StringLength(100)]` | Họ tên đầy đủ |
| `UserRole` | string | `[Required]`, `[StringLength(20)]`, default="Student" | Vai trò: Admin/Teacher/Student |
| `IsActive` | bool | default=true | Tài khoản đang hoạt động? |

**Navigation Properties**:
- `Courses`: Danh sách khóa học dạy (chỉ dùng khi là Teacher)
- `Enrollments`: Danh sách đăng ký khóa (chỉ dùng khi là Student)
- `Submissions`: Danh sách bài nộp (chỉ dùng khi là Student)

## 4. ApplicationDbContext - Cấu hình Fluent API

### Delete Behaviors:
| Quan hệ | Hành vi xóa | Lý do |
|---------|-------------|-------|
| Teacher → Course | **Restrict** | Không cho xóa Teacher nếu còn Course |
| Student → Enrollment | Cascade | Xóa Student → xóa đăng ký |
| Course → Enrollment | Cascade | Xóa Course → xóa đăng ký |
| Course → Session | Cascade | Xóa Course → xóa buổi học |
| Course → Material | Cascade | Xóa Course → xóa tài liệu |
| Course → Assignment | Cascade | Xóa Course → xóa bài tập |
| Assignment → Submission | **Cascade** | Xóa bài tập → xóa bài nộp |
| Student → Submission | **Restrict** | Tránh xung đột cascade paths |

### Unique Indexes:
| Index | Cột | Mục đích |
|-------|-----|----------|
| `IX_Enrollment_CourseId_StudentId` | CourseId + StudentId | 1 student / 1 course |
| `IX_Submission_AssignmentId_StudentId` | AssignmentId + StudentId | 1 bài nộp / 1 assignment |

// BẮT BUỘC dùng AddIdentity<AppUser, IdentityRole>

## 7. QUY TẮC BẮT BUỘC CHO TOÀN BỘ DỰ ÁN

> [!CAUTION]
> Ba quy tắc dưới đây phải được tuân thủ ở TẤT CẢ các phần sau (Controllers, Services, Views...).

### 7.1 ⏰ Chỉ dùng `DateTime.UtcNow` — TUYỆT ĐỐI KHÔNG dùng `DateTime.Now`

- Cột ngày giờ trong PostgreSQL là `timestamp with time zone`.
- Npgsql **chỉ chấp nhận** `DateTime` có `Kind = Utc`.
- Nếu dùng `DateTime.Now` (Kind=Local) hoặc `new DateTime(...)` (Kind=Unspecified) → `SaveChanges()` sẽ **crash** với lỗi: `"Cannot write DateTime with Kind=Local/Unspecified"`.

```csharp
// ✅ ĐÚNG
course.CreatedAt = DateTime.UtcNow;

// ❌ SAI — sẽ crash khi SaveChanges
course.CreatedAt = DateTime.Now;
```

- **Khi hiển thị trên View**: convert sang giờ Việt Nam (UTC+7) nếu muốn:
```csharp
@Model.CreatedAt.AddHours(7).ToString("dd/MM/yyyy HH:mm")
```

### 7.2 🔐 Đồng bộ `UserRole` với Identity Roles

Có **hai nguồn sự thật** về vai trò:
1. Cột `AppUser.UserRole` (string) — dùng để query/hiển thị nhanh
2. Hệ thống Identity (`AspNetRoles` + `AspNetUserRoles`) — dùng cho `[Authorize(Roles = "...")]`

> `[Authorize(Roles = "Teacher")]` chỉ đọc **Identity Roles**, KHÔNG đọc cột `UserRole`.

**Quy tắc khi đăng ký/tạo user (Phần 3 - Authentication):**

```csharp
// Bước 1: Gán cột UserRole
user.UserRole = "Teacher";

// Bước 2: Gán Identity Role (BẮT BUỘC để [Authorize] hoạt động)
await _userManager.AddToRoleAsync(user, "Teacher");
```

**Phải seed 3 roles** vào `AspNetRoles` trước khi tạo user:
```csharp
// Seed trong Program.cs hoặc DbInitializer
string[] roles = { "Admin", "Teacher", "Student" };
foreach (var role in roles)
{
    if (!await roleManager.RoleExistsAsync(role))
        await roleManager.CreateAsync(new IdentityRole(role));
}
```

### 7.3 🚫 KHÔNG xóa cứng User — Dùng Soft Delete (IsActive)

- `Student → Submission` có `DeleteBehavior.Restrict` → xóa student đã nộp bài sẽ **throw exception**.
- **Quy tắc cho Admin**: quản lý user bằng cách toggle `IsActive = false` (khóa tài khoản), **KHÔNG dùng Delete**.

```csharp
// ✅ ĐÚNG — Soft delete (khóa tài khoản)
user.IsActive = false;
await _context.SaveChangesAsync();

// ❌ SAI — sẽ crash nếu user có Submission
_context.Users.Remove(user);
```
